# Release v5.6.x

2026-09-11

Version description of the v5.6.0 release of SlideRule Earth.

## Significant Changes

* **v5.6.0** - [4c932c1](https://github.com/SlideRuleEarth/sliderule/commit/4c932c1d34ebe2deb01e52810a3b81a8c7e2f642) - The SlideRule MCP server has been removed.

* **v5.6.0** - [#658](https://github.com/SlideRuleEarth/sliderule/pull/658) - Rasters are now sampled at the coordinate epoch of the point (fixes [#645](https://github.com/SlideRuleEarth/sliderule/issues/645)).  Previously, when the point CRS was dynamic (ITRF2014/ITRF2020) and the raster CRS was static (e.g. 3DEP in NAD83(2011)), the transformation was evaluated at the 2010.0 reference epoch, resulting in a horizontal offset of ~0.25 m for 2024 data (growing ~2 cm/yr) along with a small vertical offset.  Sampled values for these rasters will change.

* **v5.6.0** - [#656](https://github.com/SlideRuleEarth/sliderule/pull/656) - `deriv.aspect` is now returned as a compass azimuth of the downslope direction (clockwise from north, in [0, 360)), following the `gdaldem` default convention.  Flat cells now return NaN instead of 0.

* **v5.6.0** - [#657](https://github.com/SlideRuleEarth/sliderule/pull/657) - Fixed the slope kernel normalization in `computeSlopeAspect`; for kernel half-widths greater than 1 (e.g. `slope_scale_length` larger than the native resolution), slopes were previously underestimated.  The native 3x3 result is unchanged.

* **v5.6.1** - [265e041](https://github.com/SlideRuleEarth/sliderule/commit/265e041142970872d1bff72438da4a2148a05833) - ATL24 granule discovery switched to CMR.

## New Functionality

* **v5.6.0** - [76be69c](https://github.com/SlideRuleEarth/sliderule/commit/76be69c8d13cf3eb996907e8cf1726e6f299e4cd) - New SlideRule command line tools package (`clients/cli`), starting with the `sliderule-runner` tool for submitting and monitoring jobs (with subcommands, reporting, and a `scrape` command).  Subsequent releases add `sliderule-provisioner` [ff7b327](https://github.com/SlideRuleEarth/sliderule/commit/ff7b3272ac8167fb679d025ee62df3acfa9d4382), `sliderule-cluster` [8c96589](https://github.com/SlideRuleEarth/sliderule/commit/8c96589d7c3287a23dadf60a11e3d6fdbf8fa37b), and the recorder usage report [5ebd71f](https://github.com/SlideRuleEarth/sliderule/commit/5ebd71f86f742eb2f0af2553550437f21e178c5c).

* **v5.6.0** - [21cb600](https://github.com/SlideRuleEarth/sliderule/commit/21cb6007d971bf2c49e30923640485e4bdb9a402) - Added prioritization in job queues and different job definitions for the job runner.

* **v5.6.0** - [f72bcc4](https://github.com/SlideRuleEarth/sliderule/commit/f72bcc4a4680afb8eddb506b9b0ba1e85777013a) - Added PPD/POD degrade filtering to the bathy dataframe; an alert is generated when degraded data is encountered [ae8cdf6](https://github.com/SlideRuleEarth/sliderule/commit/ae8cdf607c2f356c3ce40a3a6eb49448d9663de4).

* **v5.6.0** - [cfc87a8](https://github.com/SlideRuleEarth/sliderule/commit/cfc87a85a7b7aacbd0f2ce1167f1383de9bcd678) - Dataframe error checking before export, and duplication checking when receiving dataframes to catch retried granules.

* **v5.6.1** - [94a688e](https://github.com/SlideRuleEarth/sliderule/commit/94a688efa6e3bf1be9765b47c25401939a5fab88) - Raster sampling is performed at the granule level instead of the beam level, resulting in a ~2x speedup.

* **v5.6.1** - [a37262d](https://github.com/SlideRuleEarth/sliderule/commit/a37262d9ddde812528cec26a000dbacd3a488001) - Added the `jit_catalog` parameter for just-in-time catalog population.

* **v5.6.1** - [9fd64ab](https://github.com/SlideRuleEarth/sliderule/commit/9fd64ab2d78c1a9a96f1a08b983c0b73d0493807) - Added `bbox` option to GeoDataFrames.

* **v5.6.2** - [e1b0383](https://github.com/SlideRuleEarth/sliderule/commit/e1b03839f6cf00af62be9fc2094b3595303e9a28) - `sliderule-runner` is able to retrieve logs for child jobs.

* **v5.6.3** - [f95a9ec](https://github.com/SlideRuleEarth/sliderule/commit/f95a9ec25ef727510485d778f742b336408a62d0) - New Python job runner (`pysr`) for running user supplied Python code in the SlideRule job runner [bb40d5e](https://github.com/SlideRuleEarth/sliderule/commit/bb40d5ed48d4c9fc0a3bed24054e0385a7681fe8).

* **v5.6.3** - [d6a0025](https://github.com/SlideRuleEarth/sliderule/commit/d6a0025383fb24253ba1a76f0213f8e34383f000) - Added `s3access` handler to the provisioner for obtaining S3 access.

* **v5.6.3** - [a5f218e](https://github.com/SlideRuleEarth/sliderule/commit/a5f218e781c8dd8a9a86b163701e38665aea0caa) - Added CLI reference documentation for `sliderule-provisioner`, `sliderule-runner`, and `sliderule-recorder`.

## Issues Resolved

* **v5.6.0** - [#655](https://github.com/SlideRuleEarth/sliderule/pull/655) - integral floats (e.g. `40.0`) are now accepted for integer parameters; previously they were rejected and silently replaced with the default value

* **v5.6.0** - [68f7176](https://github.com/SlideRuleEarth/sliderule/commit/68f7176c1db77e3622edd056a9137215e4b31b8e) - the point time is carried as GPS milliseconds on every sampling path so that `use_poi_time` correctly selects the closest raster in time
